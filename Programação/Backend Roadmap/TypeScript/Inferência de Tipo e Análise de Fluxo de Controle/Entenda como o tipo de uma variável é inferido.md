Como já vimos, enquanto uma variável tem um valor único em runtime, na análise estática feita pelo TS ela possui um [[Pense nos tipos como conjuntos de valores|conjunto de valores possíveis]], seu tipo. Quando declaramos um variável mas não definimos explicitamente seu tipo, o TS precisa decidir esse tipo com base no valor que você especificou num processo chamado aqui de **widening**. 

Os principais problemas envolvendo esse processo envolvem o fato de que o Widening é ambíguo no sentido de que para que qualquer valor especificado, uma série de tipos podem ser inferidos, afinal se temos um valor, por exemplo, `['x', 1]` ele é atribuível a qualquer dos seguintes tipos: `('x'|1)[]`, `['x', 1]`, `[string, number]` , `readonly [string, number]` entre outros, de modo que sem mais contexto o TS não consegue escolher qual desses tipos é o que você pretende usar exatamente então precisa adivinhar.

Para realizar o Widening o TS parte do pressuposto que um valor declarado a uma variável não será alterado para algo completamente diferente depois e assim, tenta tomar uma decisão balanceada pesando flexibilidade e especificidade. 

Usando `let`, a regra geral para tipos primitivos é que eles se expandem para seu tipos base, `'x'` é `string`, `1` é ``number``,  `false` é `boolean` e assim por diante.

Podemos no entanto interferir no Widening de algumas formas, a mais comum é utilizando `const` ao invés de `let`, caso em que o TS passa a inferir tipos mais restritos, em especial, para os tipos primitivos, como eles não podem ser reatribuídos, temos que  `x` é `x`, `1` é `1`, `false` é `false` e ademais.

Entretanto, para objetos e listas, `const` continua com problemas de ambiguidade, esse é mais um para a lista dos problemas associados à [[Use readonly para evitar erros associados a mutação|mutabilidade]] e, como regra geral, para objetos, o TS infere seus tipos considerando as propriedades fornecidas descritas como obrigatórias e seus respectivos tipos definidos como o tipo base do valor primitivo definido (e.g. `{x: 1, y: '2'}` é inferido como `{x: number, y: string}`), para os arrays, por outro lado, o tipo inferido é um array do union type dos tipos dos valores especificados (e.g. `[1, '2']` é inferido como `(number | string)[]`). 

Uma outra forma de interferir no Widening é por meio da asserção `const` (Não confunda essa asserção como uma asserção de tipos), quando utilizamos `as const` após um valor, o TS tentará inferir o tipo da variável associada como sendo o mais restrito possível, por exemplo, `{x: 1, y: '2'}` é inferido como `{readonly x: 1, readonly y: '2'}` (Equivalente a `Readonly<typeof obj>`), também podemos fazer algo semelhante declarando o objeto usando `Object.freeze(<object>)` que reforçará em runtime a questão de não re atribuição das propriedades mas é raso, diferente de `as const` que ´´e profundo.

Também é possível fazer essa manipulação do widening usando o operador `satisfies`, usando `value satisfies T` basicamente dizemos ao TS: "esse objeto satisfaz o tipo `T`", se ele satisfaz `T`, seu tipo deve ser `T` ou um subtipo de `T` de modo que aplicando esse operador fazemos com que o widening não infira um tipo mais abrangente que `T`, ainda assim, ele pode inferir um tipo mais restrito, vale ter em mente que `satisfies` não é uma asserção de tipo e portanto ele não "confia" em você, realizando uma análise e apontando um erro caso ele  não satisfaça realmente o tipo.
