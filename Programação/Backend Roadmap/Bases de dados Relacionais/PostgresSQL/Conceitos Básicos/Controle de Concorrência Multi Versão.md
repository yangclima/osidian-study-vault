Para garantir os [[Princípios ACID]] garantindo acesso simultâneo e consistência nos dados, o PostgreSQL fornece uma série de ferramentas para os desenvolvedores. Internamente, essa consistência dos dados é garantida pelo modelo multi versão chamado MVCC (Multi-Version Concurrency Control) que basicamente se responsabiliza pela disponibilização de snapshots da base de dados para cada transaction garantindo a consistência simultânea das mesmas. Esse modelo se diferencia razoavelmente de outros modelos de locking SQL tradicionais e  minimiza o travamento dos dados permitindo um desempenho razoável em ambientes multiusuário. 

A vantagem do MVCC sobre o Locking tradicional vem principalmente do fato de que o MVCC é capaz de distinguir travamentos de dados de leitura e de escrita, de modo que aqueles de escrita nunca travam os de leitura e vice versa o que é feito mantendo ainda assim um nível rigoroso de isolamento de transactions através de um nível de **Serializable Snapshot Isolation** (SSI).

O locking tradicional, tanto a nível de linha quanto a nível de [[Noções básicas sobre tabelas|tabela]] também está disponível no PostgreSQL para aplicações que não necessitam de isolação completa ou que querem gerenciar os próprios ponto de conflito, apesar de, em geral, o MVCC ter um melhor desempenho.
